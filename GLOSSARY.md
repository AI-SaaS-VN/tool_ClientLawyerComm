# GLOSSARY.md — Business Glossary / 业务术语表

> Synchronized with SOW.md v1.11 (2026-10-03). Activation is one step: the invited email plus the activation code. Contains confirmed business terms only. New terms are registered here before they are used in SPEC/PLAN.
> 与 SOW.md v1.11 同步（2026-10-03）。激活是一步：受邀邮箱加上激活码。仅收录已确定的业务术语。新增术语先在此登记，再在 SPEC/PLAN 中使用。

| Term / 术语 | Meaning in This Project / 本项目中的含义 |
| --- | --- |
| Client Organization<br>客户组织 | The enterprise or individual entity receiving the services; not equivalent to a login account.<br>接受服务的企业或个人主体，不等同于登录账号 |
| User<br>用户 | A login identity that can be associated with one or more verified Registered Contact Channels (MVP: email only, v1.4; mobile phone P1); may join Cases it is authorized for; two accounts must not be merged merely because their names are the same.<br>登录身份，可关联一个或多个已验证的注册联系方式（MVP 仅邮箱，v1.4；手机号 P1）；可加入被授权的案件；仅凭姓名相同不得合并两个账号 |
| Case Space<br>案件空间 | The boundary of a Case's members, chats, files, Review, and Archive.<br>一项案件的成员、聊天、文件、审核与归档边界 |
| Case Coordinator<br>案件协调员 | A person granted designated permissions for invitations, member management, Publish Review, and Archive. Management and Review are separate duty flags and may be held by different coordinators on the same Case. A coordinator may participate in Case chats and post messages (v1.4, superseding v1.1 Q3). Those messages are subject to the same content checks and Audit Trail as other members' messages. If another reviewer or a backup Coordinator exists, the author cannot release their own held item. If the author is the only reviewer and no backup Coordinator is configured, the system prompts them; explicit confirmation publishes the item. Not equivalent to the System Operations Administrator.<br>获指定权限的邀请、成员管理、发布审核与归档人员。管理与审核是分开的职责标记，同一案件可由不同协调员分别承担。协调员可参与案件聊天并发言（v1.4，取代 v1.1 Q3）。其消息与其他成员的消息一样接受内容检查与审计。若另有审核人或备用协调员，作者不能放行自己被拦住的内容。若作者是唯一审核人且未配置备用协调员，系统向其提示；明确确认后发布。不等同于系统运维管理员 |
| System Operations Administrator<br>系统运维管理员 | An operator who logs in with a dedicated account for service health, configuration, and restricted administration. The account is not shared with a Case Coordinator, Client, or Lawyer, and does not join Case chat by default.<br>使用专门账号登录、负责服务健康、配置与受限管理操作的人员。账号不与案件协调员、客户或律师共用，默认不加入案件聊天 |
| In-app Confirmation<br>站内确认 | The confirmation made by the recipient, after logging in, within the Case in response to an Urgent Alert; it is the primary evidence that the alert reached the recipient; the system does not provide message read receipts to the other party.<br>收件人登录后在案件内对紧急提醒作出的确认，是提醒触达的主要证据；系统不向另一方提供消息已读回执 |
| Registered Contact Channel<br>注册联系方式 | The contact channel used for authentication and system notifications (MVP: email only, v1.4; mobile phone P1); not disclosed to other participants by default.<br>用于认证及系统通知的联系方式（MVP 仅邮箱，v1.4；手机号 P1），默认不向其他参与方公开 |
| Activation Email<br>激活邮件 | (v1.11) Sent only to the address an authorized person entered. The activation code inside is bound to that email, the Case, and the role. Only that email can accept it, in one step, on any browser, while the code is unused (codes do not expire, v1.12). Completing it grants that Case and role only. The same email accepts a later code for another Case on the same account. The same email and code sign in to that case again. Case entry does not use a 6-digit code. The administrator still uses the email OTP. The System Operations Administrator is not created this way. The repository implements this path.<br>（v1.11）只发给被授权的人输入的那个地址。其中的激活码绑定该邮箱、案件与角色。只有该邮箱可以接受，并且只做一步；激活码未使用时，任意浏览器都可以（邀请码长期有效，v1.12）。完成后只授予该案件与该角色。同一邮箱以后接受另一个案件的激活码时，加入同一账号。之后仍用同一邮箱和同一个邀请码进入该案件。案件入口不使用 6 位验证码。管理员仍用邮箱验证码登录。系统运维管理员不由此创建。本仓库已实现这条路径。 |
| Case Amount<br>案件金额 | Amounts needed to discuss the facts of a case, such as litigation claims, debts, losses, compensation, settlements, and court fees (not restricted).<br>诉讼请求、债权、损失、赔偿、和解以及法院诉讼费等讨论案情所需的金额（不受限） |
| Litigation Retainer Fees<br>诉讼委托费用 | The only fee topic under content restriction in this phase: an explicit inquiry or negotiation about what the firm charges for the case. Ambiguous mentions pass by default (v1.4).<br>本期唯一受内容限制的费用话题：就律所办理本案收取多少费用所作的显式问询或协商。模糊提及默认放行（v1.4） |
| Restricted Business Content<br>受限商务内容 | In this phase, refers specifically to content related to Litigation Retainer Fees. Direct contact channels are a separate rule. No other information may be added to this restriction without authorization.<br>本期专指诉讼委托费用相关内容。直接联系渠道是另一条规则。其他信息不得擅自扩入该限制 |
| Default Screen Language<br>默认屏幕语言 | Confirmed again 2026-10-03. A Chinese Client sees Traditional Chinese. A Vietnamese Lawyer sees Vietnamese. A Coordinator sees Simplified Chinese. Labels, buttons, placeholders, status text, and automatic-mode messages from other people use that one language. The two languages are not written together on the same control. The client may switch to Simplified Chinese or English. Simplified input is Unicode and can be shown in Traditional by character conversion; that conversion does not re-encode the text, so it does not produce mojibake.<br>2026-10-03 再次确认，当晚更正客户默认。中国客户看到繁体中文。越南律师看到越南语。协调员看到简体中文。按钮、提示、状态文字，以及自动模式下别人发来的消息，都用这一种语言。同一控件上不并列两种语言。客户可以改成简体中文或英语。简体输入是 Unicode，可以用逐字转换显示成繁体；转换不重新编码，不会变成乱码。 |
| Record Timestamp<br>记录时间戳 | Confirmed 2026-10-03. Every conversation record and every upload record the viewer can see shows a calendar date and clock time, formatted with the timezone set on that computer, and the offset is printed beside the time. A computer set to UTC+8 shows `18:45 UTC+8`. A computer set to UTC+7 shows `17:45 UTC+7` for the same instant. The role does not choose the offset. A published message uses its publish time. An author's own not-yet-published message uses its submission time. An upload uses its upload time.<br>2026-10-03 确认。观看者能看到的每条对话记录和每条上传记录，都按那台电脑的时区设置显示日期和钟点，并在旁边标出时区。设为 UTC+8 的电脑显示 `18:45 UTC+8`。同一时刻在设为 UTC+7 的电脑上显示 `17:45 UTC+7`。时区不按角色写死。已发布消息用发布时间。作者自己尚未发布的消息用提交时间。上传用上传时间。 |
| Source Text / Translated Text<br>源文 / 译文 | The text submitted by the user and its corresponding translation; the Translated Text must be traceable to the Source Text version. Translation is requested only after the Source Text is approved.<br>用户提交的文字与其对应翻译；译文必须可追溯到源文版本。只有源文获准之后才请求翻译 |
| Published Version<br>发布版本 | The specific message or file version that has passed permission and content checks and is allowed to be viewed by the recipients. In automatic mode the recipient sees a waiting prompt until the Translated Text is ready, not the foreign Source Text as a fallback.<br>经过权限和内容检查、允许接收方查看的具体消息或文件版本。自动模式下，译文就绪前接收方看到等待提示，不用外语源文代替 |
| Urgent Alert<br>紧急提醒 | A notification requesting the other party to log in and check as soon as possible; it does not mean the other party has read, handled, or committed to respond. Final delivery failure is visible to the sender and produces a content-free notice to the Case's reviewers.<br>请求对方尽快登录查看的通知，不等于对方已阅读、已处理或承诺响应。最终送达失败对发送人可见，并向本案审核人发送不含正文的通知 |
| Pending Review<br>待审 | The state in which content has been determined by checks to be suspected restricted and is awaiting manual Review by a Coordinator other than the author; not visible to the receiving party during this period. Distinct from `check_failed`, which means the check or scan itself did not finish.<br>内容经检查判定为疑似受限、等待作者以外的协调员人工审核的状态；期间对接收方不可见。与 `check_failed` 不同，后者表示检查或扫描本身没有完成 |
| Original File / Shared Copy<br>原件 / 共享副本 | The uploaded immutable original file and the copy published after Review, stored separately and linked to each other.<br>上传的不可变原始文件与经审核发布的副本，分别存储并关联 |
| Bilingual Parallel Document<br>双语对照文档 | (P1, v1.4) A Chinese–Vietnamese parallel DOCX organized by paragraph numbers, generated upon the user's active request (simple paragraph text, ≤20 pages). In MVP, document translation is handled by the participants themselves.<br>（P1，v1.4）用户主动请求生成的、按段落编号的中越对照 DOCX（≤20 页简单段落文本）。MVP 的文档翻译由参与方自行完成 |
| Daily Case Digest<br>案件日报 | (MVP as of 2026-10-04; added as P1 in v1.5) An email generated at 00:00 Asia/Ho_Chi_Minh. It summarizes the previous Vietnamese calendar day's published messages and published attachments. The only recipient is the Case Coordinator, who forwards it to other people. Lawyers and Clients are not recipients in this MVP. Subject: `{Case name}-{send date}-Record` (example: `DG-Juyang-2026OCT8-Record`).<br>（2026-10-04 起属于 MVP；v1.5 曾作为 P1 加入）在 Asia/Ho_Chi_Minh 00:00 生成的邮件。汇总上一越南日历日已发布的消息与已发布的附件。收件人只有案件协调员，由协调员转给其他人。本 MVP 不发给律师和客户。标题：`{案件名称}-{发送日}-Record`（示例：`DG-Juyang-2026OCT8-Record`） |
